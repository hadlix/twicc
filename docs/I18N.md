# Interface languages

TwiCC supports English and French. Choose **Settings → General → Interface language**.
The choice is stored on this device and synchronized between its tabs. Without a saved
choice, a French browser uses French and other browsers use English. A same-origin
language cookie also localizes the standalone password and authorization pages.

## Message catalogues

`frontend/src/i18n/en.json` uses the exact original English copy as both key and value.
Do not rewrite English when adding a translation. Add the matching French value to
`fr.json`, then call `t(source, parameters)` from the i18n module. Vue templates use
an explicit import aliased to `$t`. Vue continues to escape rendered content.

Use parameters for dynamic values rather than translating user text. Commands,
protocol identifiers, key codes, paths, model names, session content, and user-created
titles are not translated. Static menu objects use getters for translated labels so
that changing the language updates existing menus. Computed labels must read `t()`
inside the computation, rather than storing a translated string at module startup.

Built-in tips and help have French Markdown counterparts under `public/tips/fr/`
and `public/help/fr/`. Keep their filenames and platform/provider constraints identical
to the English files. Help and tip caches include the language in their keys.

CodeMirror phrases and Web Awesome's French locale cover embedded controls.
Standalone Python-rendered forms and pages translate fixed copy only; the API and
authorization protocols retain their original values.

## Validation

From `frontend`, run `npm run check:i18n`, `npm test`, and `npm run build`.
The catalogue check verifies matching keys, unchanged English, template coverage,
and several protocol-field invariants. The i18n tests verify language switching,
persistence, interpolation, navigation identifiers, and French help coverage.
Python page tests are in `tests/test_i18n_auth_labels.py`.

Two upstream browser-baseline tests reference commits `f5d52630` and `56a1600a` that
are absent from the available upstream history. They fail before their assertions
when running `git show`; the language implementation does not skip these tests.
